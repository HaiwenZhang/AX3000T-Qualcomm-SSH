# AX3000T 高通 RD03v2 / 原厂 2.0.28 操作指南

## 一、设备和联网准备

1. 先按 [README 的环境安装步骤](../README.md#自行安装环境) 自行安装 Python 和依赖，再继续以下操作。

   仅支持高通 IPQ5018 的 RD03v2、原厂 2.0.28，不要套用联发科 RD03/RD23 教程。
   工具读到不支持的型号/版本会停止；不要删除型号或网络模式检查。
2. 从原后台备份配置并另行保存 WAN 类型、拨号账号/密码、静态地址、DNS、VLAN、
   Wi-Fi 和自定义 DHCP 等信息。原后台密码不等于宽带拨号密码。
3. 用网线连接电脑和路由器的 LAN。只接一台待操作路由器；暂时关闭电脑 Wi-Fi，
   避免两台相同默认地址的路由器导致连错。
4. 双击 00-本地检查.cmd。看到 Offline dependencies and source hashes OK 即可。
   这个入口不访问路由器；Python 和依赖自行安装完成后，断开互联网也能继续。
5. 双击 01-查看路由器.cmd，核对硬件 RD03v2、固件 2.0.28 和当前这台的 SN。
6. 右键 05-允许临时通信.cmd，以管理员身份运行。
   它只新增“启动器实际选择的 Python + 指定路由器 IP + TCP/8000”的入站规则，
   不关闭 Windows 防火墙。复制/移动文件夹后，需要在新位置重新允许。

## 二、进入公开方法需要的状态

1. 只有确认恢复上网的信息已保存之后，再按小米官方方法手动恢复出厂。
2. 等路由器启动，继续用网线连接。电脑通常会获得 192.168.31.x 的有线地址。
   可在 PowerShell 用 ipconfig 查看，必要时重新插拔电脑侧网线后等待 DHCP。
3. 不要完成网页里的小米设置向导，不要先设置 Wi-Fi 或导入旧备份。
   正常向导会设置 NETMODE=4，阻挡本工具采用的 CAP root 路径。
4. 双击 02-最小初始化.cmd。核对 SN 后输入 INIT。
   这一步仅做最小初始化并重启，等待 Initialization complete。
5. 若提示 already initialized、型号不符、请求失败，应停止并阅读错误，
   不要接着运行后续步骤，也不要强行更改代码里的 gate。

## 三、开启 SSH 和设置密码

1. 双击 03-开启SSH.cmd，核对设备和监听 IP。
   从双网卡环境运行时，监听 IP 必须能被路由器通过网线访问。
2. 第一个密码同时用于 SSH root 和小米后台；第二个是临时 Wi-Fi 密码。
   两者均为 10-63 位不含空格的可打印 ASCII 字符，各输入两次。
   输入时不显示字符；不需要原先那台路由器的 SN 密码或后台密码。
3. 输入 ENABLE 才开始写入载荷。工具在这之前还会再检查 SN 和网络模式。
4. 等待，保持网线和电源，不要反复点击开启入口。
   Wi-Fi 可能短暂中断，载荷会把临时加密字段修复成 WPA2 和你设置的临时密码。
5. 成功信息应包含：
   SUCCESS: root SSH login verified.
   WEB_PASSWORD_OK
   PERSISTENCE_FILES_OK
   工具会真正登录 SSH 执行 id，并用普通密码登录接口验证后台密码。
   单个 API 返回 code=0 不等于全部成功。
6. 如果显示 SSH 成功但后台或持久化验证失败，不要重跑漏洞触发，保持现有 SSH，
   按下面的故障说明诊断。开启动作可能是一次性的。

## 四、验证和恢复网络

1. 双击 04-验证SSH和后台.cmd，输入当前 SSH root 密码。
   后台密码若与 root 不同，可按提示选择分别输入。
2. 手动连接 SSH 可在 PowerShell 执行：

```powershell
ssh root@192.168.31.1
```

   若明确报错对端只提供 ssh-rsa，可针对这个连接使用：

```powershell
ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1
```

3. SSH 和后台都确认后，再在后台按你保存的信息恢复 WAN 和 Wi-Fi。
   整包恢复旧备份对新增补丁的影响没有验证，优先手动恢复必要配置。
4. 上网配置恢复后先再次验证；如重新完成向导导致 root 密码改变，
   使用你自己的 SSH 管理方式重新设置密码，不能假定其他设备的 SN 密码通用。
5. 测试一次路由器重启，等待 90 秒，再运行 04-验证SSH和后台.cmd。
   原因：/etc/init.d 在内存盘中；补丁保存在持久化的 /etc/crontabs/patches，
   cron 每分钟检查并在新启动后重新修改原厂 Dropbear 启动限制。
6. 每台路由器分别验证，不把第一台成功当作所有机器成功。
7. 完成后右键 06-删除临时规则.cmd，以管理员身份运行。
   该规则只用于开启过程，删除它不会关闭路由器的 SSH。
8. OTA、恢复出厂或其他管理工具可能覆盖补丁，本工具不保证跨 OTA 保持。

## 五、在其他电脑/位置使用

复制本代码目录，在接收电脑上重新按 README 安装 Python 和 requirements.txt 中的依赖，不复制本机 .venv。
不需要把 xmir-patcher、分析用固件、WSL、Java、pip 或原父目录一起复制。
启动脚本面向 Windows x64，推荐自行安装 Python 3.13 x64；没有随附解释器或 SSH 库。
app/sources.json 校验原始方法模块；本目录没有依赖旧分发包的 manifest.json。
本包没有密码、SN 白名单、旧日志或用户配置；每次从设备读取实际身份。

## 六、高级参数（仅在你确实更改了地址/端口时使用）

在此文件夹打开 PowerShell。以下命令使用你按 README 创建的本地虚拟环境：

```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --status
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --init
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --enable
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --verify
```


例：目标为 192.168.8.1，电脑有线地址为 192.168.8.2，临时端口用 8001：

```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --host 192.168.8.1 --status
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --host 192.168.8.1 --init
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --host 192.168.8.1 --port 8001 --local-ip 192.168.8.2 --enable
```


```powershell
.\.venv\Scripts\python.exe .\app\offline_ssh.py --host 192.168.8.1 --verify
```

仅接受 RFC1918 私有 IPv4，不接受公网、主机名或任意 URL。
--local-ip 仅指定载荷服务器地址，不会修改电脑路由；应先保证系统确实通过有线到达目标。
Reset 可能恢复默认地址，初始化和开启时必须使用设备当时的实际地址。

防火墙参数需与开启过程一致，在管理员 PowerShell 运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\firewall.ps1 -Action Add -RouterIp 192.168.8.1 -Port 8001
```

完成后使用同样的 RouterIp/Port，把 Add 改为 Remove。删除防火墙规则后再移动或删除本机虚拟环境，确保规则能够按原解释器路径定位。
这些参数也可以传给对应 .cmd 入口；默认入口使用 192.168.31.1:8000。

## 七、故障处理

- NETMODE=4：不是密码错误，而是 root 路径被当前设置状态阻挡；不能跳过检查。
- Connection refused：尚未进入密码认证阶段；核对设备/地址，重启后先等 90 秒。
- SSH 成功但后台密码失败：不要重置或再次触发。进入该设备的 SSH 命令行执行：

```sh
lua -e 'io.write("New web password: "); local p=io.read("*l"); assert(p and #p>=10); assert(require("xiaoqiang.util.XQSecureUtil").savePlaintextPwdEx("admin",p)); print("OK")'
```

  输入新后台密码（该简易输入会显示字符），看到 OK 后用浏览器隐私窗口登录。
- SSH 成功但补丁文件未验证：先保持 SSH 会话，不要重启。
  可只读检查：

```sh
ls -l /etc/crontabs/patches/rd03v2-ssh.sh
```


```sh
grep -F /etc/crontabs/patches/rd03v2-ssh.sh /etc/crontabs/root
```


```sh
/etc/init.d/cron enabled; echo $?
```

- 触发后超时：不要马上重置或反复触发。若还能通过 SSH 连接，可读取：

```sh
cat /tmp/offline-ssh.log
```

  分享日志前自行检查是否包含隐私。工具不会自动把日志上传到外部服务。
- 本机端口占用：换一个端口并对应更改临时防火墙规则，或关闭占用端口的本机程序。
- 原本正常的路由器也出现问题：立即核对设备 SN，不要依靠相同默认 IP 判断身份。
- 不支持的版本：先停止，不降级或刷入别的硬件版本固件。

## 八、改动和验证范围

--init：修改最小初始化状态并重启。
--enable：通过公开 Mesh 方法取得执行能力；临时改写并修复 Wi-Fi 字段；
设置 root/后台密码；设置 ssh_en；部署 cron 补丁；启动 SSH。
--verify：读取状态文件、执行 id 和进行一次后台登录验证，不重启或改网络配置。
本工具不扫描邻居设备、不自动恢复出厂、不刷固件、不安装 OpenWrt。
本地测试不等于每台设备的实机验证，重启保持必须由每台设备的重启后验证来确认。
